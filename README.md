# God's Hand of Principality and Demise

A rhythm duel in the style of Friday Night Funkin', written from scratch in **C++20** with its own glossy cartoon cast, merged with the best of **PulseForge**:
it plays Psych Engine mods (Lua and HScript, characters, stages, events, shaders, videos), full Kade/base-game builds and
spam charts of any size, has chart, character, stage, event and script editors, charts any song by itself, records replays and videos,
and installs mods from `.zip`. A project by **deatuamae67-crypto**.

*Um duelo de ritmo ao estilo de Friday Night Funkin', escrito de raiz em C++20 e unido ao melhor do PulseForge. Um projeto de deatuamae67-crypto.*

**Downloads:** [Releases](https://github.com/deatuamae67-crypto/Gods-Hand-of-Principality-And-Demise/releases)

## Português

### O que é
- **Jogo de ritmo tipo FNF**: o adversário canta, tu respondes. Setas a subir (ou a descer), notas longas (*holds*), barra de vida, combo, pontuação, precisão e ranks.
- **4 músicas originais** sintetizadas em C++ no arranque (bateria, baixo, pads, sinos e vozes "cantadas"), com charts gerados das próprias melodias. Personagens de desenho animado com acabamento brilhante "Frutiger Aero" (Hype, Principal P, DJ Hand e D-Mize) e cenários (um telhado de escola ao pôr do sol, uma discoteca, um beco punk) desenhados em código.
- **Rápido e preciso**: o relógio da música vem do mixer de áudio, o input é lido ~1000 vezes por segundo com *timestamp* e o julgamento não depende dos FPS.

### Mods
- **Psych Engine a sério**: personagens (`characters/*.json` + atlas Sparrow), ícones, cores da barra de vida, cenários (`stages/*.json`, incluindo objetos do editor 0.7.3), eventos, tipos de nota e **scripts Lua 5.4** com a API do Psych (326 funções, todas na [wiki](docs/wiki/Lua-API.md): sprites, textos, tweens, timers, câmaras, propriedades, grupos de notas e strums, sons com tempo e *pitch*, dados guardados, *substates*, definições do mod, `Function_Stop`) e modcharts do Kade Engine.
- **HScript**: `runHaxeCode`, `runHaxeFunction`, `createCallback` e ficheiros `.hx` (em `scripts/`, `stages/`, `data/<música>/`...) com `game`, `FlxG`, `FlxSprite`, `FlxText`, `FlxTween`, `FlxTimer`, `FlxColor`, `ShaderFilter`, `new Character(...)` (personagens extra), `MP4Handler`/`VideoHandler`, `FlxG.cameras`, nomes completos `openfl.*`/`flixel.*`/`lime.*`...
- **Compatível com o JS Engine**: os eventos dele (Set/Tween Camera Zoom, Camera Bopping, Camera Twist, Change Note Multiplier, Fake Song Length, Change Song Name, Credits Popup, Popup, Rainbow Eyesore, Bot Energy...), os efeitos de ecrã (`addChromaticAbberationEffect`, `addVCREffect`, `addWiggleEffect`, `addBloomEffect`, `add3DEffect`... com o GLSL do próprio JS Engine) e funções como `require`, `saveFile`, `loopTheSong`, `playsAsBF`. A câmara segue o Psych (`camFollowPos` é a posição real, foco por secção com `gfSection`, `isCameraOnForcedPos`); scripts que mudam `FlxG.width` (ex.: *Window Changer*) estreitam a imagem para 4:3.
- **Shaders**: os `.frag` do Psych/Flixel (`#pragma header`, `flixel_texture2D`) são traduzidos para OpenGL 3.3 e funcionam em sprites (`setSpriteShader`) e em câmaras inteiras (`setFilters` em HScript). Num sprite de `makeGraphic` o shader vê a imagem inteira (coordenadas de 0 a 1), e `os.clock()` conta o tempo real em todos os sistemas, como no Windows: os shaders animados com `iTime` mudam suavemente.
- **Vídeos**: `startVideo` (cutscenes, ENTER salta) e `makeVideoSprite`. Ficheiros `.mpg` tocam diretamente; `.mp4`/`.webm` são convertidos uma vez com o **ffmpeg** (se estiver instalado ou ao lado do jogo) para `cache/videos/`.
- **Builds completas do Kade / jogo base** (pasta `assets/` com `shared/`, `week1`...): as personagens e cenários das semanas 1–6 são reconstruídos a partir das imagens do mod.
- **Qualquer formato de pasta**: mods do Psych, pastas dentro de pastas, charts soltos (agrupados por música, com o áudio procurado em todos os mods), V-Slice, builds completas com os charts em `assets/preload/data/` ou `assets/shared/data/` e o áudio em `assets/songs/` (Psych 0.4–0.7, H-Slice, Psych EK), a pasta `mods/` de uma build com mods lá dentro, `data/charts/<música>/`, charts soltos em `data/`, a build compilada dentro do código-fonte (`export/release/.../bin/`; cópias iguais de um chart aparecem uma vez só, versões diferentes aparecem as duas com a pasta de onde vêm), **charts do PulseForge** (`chart.json` exportado, projetos `.pfchart.json` e *autosaves* do editor) e **pastas só com áudio** (cada música com 30 s ou mais ganha AutoChart; efeitos sonoros curtos ficam de fora). 1 a 100 teclas (`keyCount` até 100, ou `mania` do Dave & Bambi / Kade / Andromeda, Psych Extra Keys até 18 teclas (`mania` 17), Denpa (`options.mania`) e Shaggy: as notas decidem qual numeração o chart usa, e um `mania` que as notas não usam — como o `options.mania` dos charts de spam do JS Engine — dá 4 teclas; sem nada disto o chart tem 4 teclas, como no Psych). Os charts do Leather Engine com teclas diferentes para cada lado (`keyCount` e `playerKeyCount`) jogam-se assim, e os scripts que imitam teclas extra num jogo de 4 teclas (o *Extra Keys Script* dos mods do JS Engine) não correm, porque o jogo já as toca. Opções → "Extra keys" OFF joga tudo com 4 teclas, como o Psych e o JS Engine. De 19 a 100 teclas as pistas estreitam para caber e usam as teclas do teclado fila a fila (43 teclas); as pistas a mais toca-as o bot.
- **Charts de spam gigantes**: um chart de 1,5 GB (25 milhões de notas) abre em ~5 s. As notas empilhadas no mesmo milissegundo ficam juntas em memória mas **contam todas** (acertos, combo, pontuação, total no fim), e as notas desenham-se até 1 pixel de distância (com Opções → "Note detail: Adaptive", se o FPS ficar abaixo de 60 com centenas de notas no ecrã, as notas empilhadas a menos de 2–32 px desenham-se uma vez; todas continuam a ser tocadas e contadas). Charts sem número de teclas são de 4 teclas, como no Psych/JS Engine.
- **A música começa logo**: o áudio é descodificado enquanto toca (ideia da S2X, que lê o chart enquanto a música corre). Uma música de 3 minutos fica pronta em ~2 ms em vez de 0,75 s, uma de 1 hora em 2,5 ms em vez de 6 s (e gasta 21 MB em vez de 1,2 GB), e a de 8 horas do LONGSONG (Desert Bus) já não fecha o jogo. As músicas compridas guardam em memória só os minutos à volta do ponto em que estão; a pré-visualização do Freeplay também começa logo.
- **Assets partilhados entre mods**: quando um mod usa uma personagem, cenário, imagem, som, vídeo, shader ou letra que não tem, o jogo procura-o primeiro no resto do próprio pacote e depois em todos os outros mods instalados (os pacotes só de assets, como `lmac-orien-sprites` e `lmac-denpaex-reconstructed`, servem para isto). Um cenário, personagem, tipo de nota ou evento emprestado traz o seu próprio script; os scripts globais do outro mod (`scripts/`) não correm. Exemplo: o *autosave* "18th-Victim" do pacote `pulseforge-created` joga com o cenário, as personagens, os ícones e o áudio do pacote vs dinnerbambi.
- **Windows**: pastas e ficheiros com nomes em qualquer alfabeto (chinês, japonês, cirílico...) abrem (código UTF-8 no executável, Windows 10 1903 ou mais recente).
- Os scripts correm isolados (sem `io` nem `os`; `require` só lê módulos do próprio mod, `saveFile` só escreve dentro de `mods/`) e param se entrarem em ciclo infinito.

### Também
- **Editor de charts** (Freeplay → `7`), ao estilo do Psych/JS Engine: separadores **Song** (nome, personagens, cenário, BPM, velocidade, teclas), **Section** (lado da câmara, *GF section*, *alt animation*, duração em batidas, BPM; copiar, colar, limpar, trocar lados, espelhar, copiar de uma secção anterior), **Note** (tipo, tempo, *hold*, notas empilhadas; ferramentas de spam: empilhar e preencher a secção em escada, aleatório, zigue-zague...), **Events** (pista de eventos à esquerda, vários eventos no mesmo tempo, lista com os do Psych, do JS Engine e os `custom_events` do mod, com a explicação dos valores) e **Charting** (velocidade de reprodução, volumes, *hitsounds*, metrónomo). Seleção com SHIFT+arrastar, desfazer/refazer. Guarda em JSON do Psych (o original fica como `.bak`); `ENTER` guarda e joga.
- **AutoChart**: uma pasta só com o áudio (ou um `.mp3`/`.ogg` solto em `songs/`) ganha charts Easy/Normal/Hard gerados a partir da música; abre-os no editor para os afinar.
- **Replays** (`R` nos resultados), **mods por `.zip`** (põe em `mods/`, `R` no Freeplay), **controlos táteis** (Opções).
- **Interface do Psych Engine** (Opções → INTERFACE): ao ligá-la, o jogo procura sozinho uma cópia do Psych Engine / JS Engine que já tenhas — engines instaladas como pacotes de mods (JS Engine, H-Slice, EZ edition...) ou uma engine (como a S2X) dentro ou ao lado da pasta do jogo — e usa a mais completa. O jogo passa a usar as setas, ratings, contagem, barra de vida, letra e sons dessa pasta, mas não traz nenhum desses ficheiros.
- **Opções novas**: VSync (aplica logo, também no Android), Shaders (desligar ajuda em telemóveis fracos); "Camera zoom on beat" só desliga os *bops* — os eventos de zoom funcionam sempre.
- **Eventos de zoom como no Psych / JS Engine**: "Add Camera Zoom" soma-se ao zoom e fica até à primeira nota tocada (de qualquer lado); só depois a câmara volta ao zoom normal (o Eons afasta a câmara no início e aproxima-a a cada compasso da introdução).
- **Interface do Psych mais completa**: com a Interface do Psych ligada, também a barra de tempo (`timeBar.png` e o tempo em `vcr.ttf` 32), o BOTPLAY a piscar, a pontuação que cresce a cada nota, o menu de pausa com as letras do Alphabet do Psych (Resume, Restart Song, Options, Exit to menu), a música `breakfast` e o contador "Blueballed". Opções novas: "Hit popups" (desligar os ratings e números de combo), "Time bar" (tempo restante, tempo decorrido, nome da música ou desligada) e "Health bar opacity".
- **Volume em todo o jogo**: `-` e `=` (ou `+` do teclado numérico) baixam e sobem o volume geral, `0` silencia logo, como no Flixel/Psych; aparece o volume no topo do ecrã. Num ecrã que use essas teclas (uma pista, a escrever no editor) elas ficam para ele.
- **A meio de uma música**: `7` abre o editor de charts nessa música e dificuldade; o menu de pausa tem **Opções** (ao sair, a música recomeça, como no Psych).
- **Opções → DEBUG**: "Lua errors" e "Lua warnings" — sempre, só com `luaDebugMode` (como o Psych) ou desligados. Os `debugPrint` dos scripts aparecem sempre. "Lua note callbacks" OFF deixa de chamar `goodNoteHit`, `opponentNoteHit`, `noteMiss` e `noteMissPress` a cada nota (mais rápido em charts de spam; mods que contam notas ou tiram vida com eles deixam de o fazer), como a opção da S2X.
- **Render Mode** (menu principal → RENDER MODE, no PC e no Android; as definições do vídeo estão em Opções → RENDER MODE VIDEOS), como no JS Engine e no H-Slice: a música toca sozinha (botplay) e é gravada num vídeo em `renders/`, frame a frame. O tempo do jogo avança exatamente 1/FPS em cada frame, por isso o vídeo sai fluido mesmo que o computador não consiga desenhar em tempo real; a janela mostra o que está a ser gravado e quanto falta. Escolhes o tamanho (1280x720 a 3840x2160), os frames por segundo (30 a 240), o codificador (Auto — o da placa gráfica, quando funciona neste computador —, x264, x265, VP9/WebM ou os da placa gráfica NVIDIA, AMD e Intel), o bitrate e se leva o som (o instrumental e as vozes, misturados pelo próprio jogo em sincronia com a imagem). No PC precisa do **ffmpeg** ao lado do jogo ou instalado; os frames saem da placa gráfica sem a fazer esperar (lidos dois frames depois) e são codificados numa thread própria enquanto o jogo desenha os seguintes. No **Android** usa o codificador do próprio telemóvel (H.264 e AAC, sem ffmpeg) e o vídeo vai para a pasta **Movies/GodsHand** (Android 10 ou mais recente), onde a galeria o mostra. `ESC` (ou o botão STOP nos ecrãs táteis) para a gravação e o vídeo fica com o que já foi gravado. Pela linha de comandos: `godshand --autoplay <música> --render`.
- **Ecrã de depuração** (`F3` numa música, como o *debug menu* da S2X): chart, relógio (tempo, batida, passo, secção), áudio (blocos descodificados e MB em memória), notas desenhadas, frames por segundo e tempos de atualização/desenho, scripts. `godshand --perf` escreve os tempos de cada segundo na consola.
- **Editor de charts**: separador **EZ Spam** (como o do JS Engine): spam na secção, daqui até ao fim, na música toda ou num intervalo de secções, com notas por batida, padrão (pista única, escadas, aleatório, zigue-zague, acordes, jacks), lado, notas longas e notas empilhadas; também limpar e desbastar (1 em 2). **FL Studio (SNIFF)**: larga um `.flp` ou `.fsc` no editor e as notas do padrão (C3–D#3 jogador, C4–D#4 adversário, F3/F#3 câmara, A3/A#3 animação alt) passam para o chart; projetos do FL Studio feitos assim dentro dos mods aparecem como músicas (cada padrão é uma dificuldade).
- **Editores** (menu principal → `7`), como o *Master Editor Menu* do Psych: escolhe o mod com ESQUERDA/DIREITA (é aí que os editores gravam) e abre o editor de charts ou um dos novos:
  - **Editor de personagens**: o JSON da personagem desenhado como numa música; as animações (com os nomes que a imagem tem, para escolher o prefixo), os offsets com as setas (SHIFT ×10) sobre o fantasma da primeira animação, imagem, escala, flip, antialiasing, ícone e cor da barra de vida (ou a cor do próprio ícone), posição, ponto da câmara e duração do canto. `CTRL+S` grava em `characters/<nome>.json`.
  - **Editor de cenários**: o JSON do cenário com os seus objetos, os sprites do script Lua e três personagens, que se arrastam com o rato para o lugar; zoom, velocidade da câmara, cenário pixel, esconder a GF, offsets da câmara e o que a câmara mostra em cada personagem. Grava em `stages/<nome>.json`.
  - **Editor de eventos**: cria eventos para os charts (`custom_events/<nome>.txt` e `.lua`) a partir de modelos (flash, esconder o HUD, tremer, zoom, som, velocidade do scroll) e abre o script no editor de texto do sistema.
  - Os ficheiros gravados mantêm os campos que os editores não conhecem.
- **Editor de charts**: o separador EZ Spam passou a ser o do JS Engine (Note Spamming: spam, esticar, deslocar e duplicar notas), os eventos escolhem-se numa lista, compassos ímpares (7/16, 5/4...), copiar e cortar secções inteiras, `SHIFT+A`/`SHIFT+D` saltam 4 secções e o *hitsound* do adversário é igual ao do jogador.
- **Interface do Psych igual à do 0.7.3**: barra de vida, ícones (150 px no topo da barra, a crescer a cada batida), pontuação, barra e texto do tempo (escondidos até a música começar), BOTPLAY e ratings/números do combo nas posições, tamanhos e animações do PlayState do Psych, e a letra `vcr.ttf` no tamanho certo (saía 14% maior). Opções do Psych: **Hide HUD**, **Score text zoom on hit**, **Botplay text**, **Combo stacking**, **Pause screen song** (None, Breakfast, Tea Time) e **Opponent notes**.
- **As restantes opções do Psych**: *Rating offset*, janelas de **Sick!**, **Good** e **Bad** e *Safe frames* (mudam mesmo o julgamento das notas; os replays guardam-nas), *Auto pause* (a música pausa quando a janela perde o foco), *Disable reset button* (sem ela, `R` acaba a música, como no Psych), *Anti-aliasing*, opacidade dos *splashes*, **Note skin...** (um ecrã próprio: as `NOTE_assets-<nome>.png` da cópia do Psych que usas e de todos os mods instalados, com as notas da skin escolhida a passar ao lado, como numa música), **Note colors...** (matiz, saturação e brilho de cada seta, com pré-visualização) e a posição dos ratings e do combo. Os scripts que perguntam por estas opções (`ClientPrefs`, `getPropertyFromClass`) recebem os valores escolhidos.
- **Scripts que mexem no HUD**: os *fades* (`doTweenAlpha` em `scoreTxt`, `timeTxt`, `timeBar`, `healthBarBG`...) fazem mesmo *fade*, e `setProperty` move, roda e escala a barra de vida, os ícones, a pontuação, a barra e o texto do tempo e o BOTPLAY, como no Psych. Começam nas posições do PlayState do Psych 0.7.3 (`getProperty('healthBar.y')` dá 640.8), e a pontuação mostra logo o que os scripts mudam (`addScore`, `setScore`, `setRatingName`...).
- **O mod da música primeiro**: a letra, a barra de vida, as notas, os ratings e os sons que o mod da música traz têm prioridade, como no `Paths` do Psych.
- **Definições na pasta do utilizador**: `%APPDATA%\GodsHand` (Windows), `~/Library/Application Support/GodsHand` (macOS), `~/.local/share/GodsHand` (Linux), a pasta da app (Android). Atualizar o jogo já não as perde (as antigas são copiadas na primeira vez; com um `portable.txt` ao lado do jogo fica tudo na pasta do jogo).
- **Velocidade do scroll no Freeplay** (`Tab`, modificadores): a do chart, multiplicada, ou constante.
- **Efeitos do JS Engine iguais aos originais**: `addBlockedGlitchEffect`, `addVCREffect`, `addGrainEffect` e os outros usam o GLSL do `Shaders.hx` do JS Engine (antes eram imitações).
- **Contador de FPS detalhado** (Opções → GRAPHICS): memória do jogo e o pico, tempos de frame com gráfico, uso do processador, da placa gráfica (quanto está ocupada e a memória de vídeo, no Windows, Linux com AMD ou NVIDIA, macOS e telemóveis Adreno/Mali que o deixem ler) e da RAM do sistema, nome do processador, da placa gráfica, versão do OpenGL e sistema. Fica vermelho abaixo de metade do limite de FPS, como no Psych.
- **Desenhador de notas** (Opções → GRAPHICS → "Note renderer"): as notas desenhadas pela placa gráfica (**GPU**) ou pelo processador, com uma rotina em **assembly** — **CPU (x86 ASM)** com SSE2 nos PCs x86-64, **CPU (ARM64 ASM)** com NEON nos telemóveis Android e nos Mac com Apple Silicon — ou em **C++** — **CPU (C++)**. No processador, cada nota é uma imagem feita uma vez (com a skin, as cores e o tamanho) e misturada numa imagem do ecrã, linha a linha e só nas colunas onde há seta, que vai para a placa gráfica de uma vez. **Auto** (o normal) usa a placa gráfica, ou o assembly quando o próprio OpenGL corre no processador (llvmpipe, SwiftShader...), onde é mais rápido. Notas rodadas e minas ficam na GPU. O assembly dá exatamente os mesmos píxeis que o C++ (os testes comparam-nos, também no Windows e num Mac ARM) e é cerca de 3× mais rápido. `F3` e `godshand --perf` mostram o tempo que leva.
- **Latência mínima**: com V-sync, a opção **Low latency** (Opções → GRAPHICS, ligada por omissão) não deixa frames à espera no driver e começa cada frame o mais tarde possível antes do ecrã o mostrar, lendo as teclas a cada milissegundo entretanto (num ecrã de 60 Hz simulado: ~5 ms da tecla ao ecrã em vez de 16,7). **Audio latency** (Opções → GAMEPLAY) escolhe o buffer da placa de som: 6, 15 (o normal, antes eram 30), 30 ou 60 ms. Sem V-sync, o jogo já lê as teclas ~1000 vezes por segundo.
- **Carregamento rápido**: as imagens das personagens e dos cenários são descodificadas em todos os núcleos do processador ao mesmo tempo (12 imagens de 2048x2048: 0,65 s em vez de 2,6 s). Os charts a partir de 8 MB são lidos em streaming por uma thread própria à frente do parser, com as secções repartidas por todos os núcleos e os caracteres estruturais do JSON encontrados 64 bytes de cada vez com instruções SIMD (SSE2 no x86-64, NEON no ARM64): um chart de 20 MB carrega em ~40 ms (antes 134 ms), um de 200 MB em ~0,3 s (antes ~0,6 s) e 3 GB do chart de 1,4 mil milhões de notas em 3,2 s em vez de 7,7 s (o chart inteiro, 33 GB, ocupa só ~300 MB de memória). Os números do JSON com até 18 algarismos (como o Haxe os escreve) já não passam pelo `strtod`. Os charts grandes ficam numa cache (`cache/charts/` na pasta do utilizador, até 4 GB): da segunda vez, um de 200 MB carrega em 0,2 s. O resultado é sempre exatamente o mesmo que lido num só núcleo (os testes comparam-nos). `godshand --perf` mostra onde vai o tempo de carregamento.
- **Contador de notas** (Opções → INTERFACE → "Note counter"): por baixo da pontuação, as notas do teu lado (`Notes 5,678 / 83,290`) ou dos dois lados somados, como no H-Slice (`Notes 1,234 + 5,678 = 6,912 / 166,603`), com o NPS de cada lado separado (adversário / tu). Pontuação, combo, falhas e contagens são de 64 bits (sem limite prático) e os números compridos encolhem para caber no ecrã.
- **Camadas de shaders**: vários shaders no mesmo sprite, cada um sobre o que o anterior desenhou, com `addSpriteShader`, `removeSpriteShader`, `getSpriteShaders`, `moveSpriteShader` e `setSpriteShaderOrder`; `setShaderFloat` e as outras recebem a camada (a posição ou o nome do shader). Ver a [wiki](docs/wiki/Shaders.md).
- **HScript mais fiel**: *comprehensions* (`[for (i in 0...4) i * i]`), funções com `return` sem chavetas, grupos (`FlxTypedGroup`, `FlxSpriteGroup`), `game.members`, `Date`, `Type`, `Sys`, `FlxEase` chamado como função, `velocity` e `acceleration` como no Flixel; `createInstance`/`addInstance` do Psych 0.7.3. Os scripts com várias personagens (como o *old.lua* do Expunged) funcionam.
- **Tweens nos objetos do HUD**: `doTweenY`, `doTweenAlpha`... chegam a `iconP1`, `healthBar`, `scoreTxt` e aos outros, e `setObjectOrder` funciona como no Psych (também com sprites ainda não adicionados).
- **Atlas difíceis**: frames que saem da imagem são cortados como no Flixel e frames com o mesmo nome ficam com o primeiro, como no Flixel (a pose da direita do scrodo-v2).
- **Editor de charts para charts de milhões de notas**: só desenha o que está no ecrã, uma nota por linha de píxeis, textura a textura, e o *undo* só guarda o que mudou (3,42 milhões de notas, com OpenGL por software: 45 ms por frame em vez de 110, 20 ms numa janela pequena). Também **Reload audio** e **Reload chart**, números escritos à mão em todos os campos (clica no número), o volume dos *hitsounds* de cada lado, "Sections back" sem limite, copiar um intervalo de secções (como o JS Engine), **Exact placement** (uma nota no início de uma secção logo a seguir a uma no fim da anterior) e uma pré-visualização do chart numa janela pequena.
- **Hitsounds granulares**: cada nota toca na sua própria amostra da música e as notas não se somam: um spam rápido vira um tom à frequência das notas (16 notas por passo a 520 BPM soam a 555 Hz) em vez de um barulho alto e estalado.
- **Charts binários `.ghc`**: o chart com as notas em colunas comprimidas, lidas em todos os núcleos: um chart de 3,42 milhões de notas passa de 201 MB para 2,4 MB (84,6× mais pequeno) e carrega em 150 ms em vez de 240. Faz-se no **Chart Converter** (menu de editores) ou no editor de charts, que grava como JSON do Psych, `.ghc` ou os dois; o `.ghc` é escrito diretamente das notas, por isso um chart grande demais para JSON pode ficar só em `.ghc`.
- **Editor de scripts** (menu de editores): os scripts Lua e HScript e os shaders do mod, editados no jogo. **Editor de cenários com objetos**: escolher, arrastar, propriedades, camadas, adicionar, copiar e apagar os objetos do JSON, gravados como objetos do Psych 0.7.3; o cenário corre no editor com os scripts e os shaders.
- **Wiki** em [`docs/wiki`](docs/wiki/Home.md): as 326 funções Lua, as callbacks, o HScript, os shaders, os formatos de chart, os editores, os mods e todas as opções.
- **Visualizador de áudio** (Opções → INTERFACE → "Audio visualizer"): barras arredondadas e brilhantes num painel de vidro no canto superior direito das músicas, que mexem com o som (FFT do que se ouve, de 40 Hz a 16 kHz; cada barra sobe logo e cai devagar). Uma linha de luz passa pelos topos, os picos ficam como pontos um momento, as barras altas brilham, há um reflexo por baixo de um chão de luz, e o aro do painel acende com os graves. A cor segue o chart: a cor de quem canta naquela secção, mais quente quanto mais notas houver, um arco-íris a correr nos spams, um clarão da cor do rating a cada nota tua, vermelho e a tremer quando falhas e a pulsar com a batida quando tens pouca vida. Só aparece nas músicas.
- **Marca de água**: "God's Hand Engine v.2.0.0 Windows Slop Edition" (a versão e o sistema) no canto inferior esquerdo das músicas, como o JS Engine (Opções → INTERFACE → "Watermark").
- **Intro do motor**: o vídeo "We do a little bit of trolling" antes do ecrã de título (`assets/videos/intro.mpg`, 3 min 28 s em MPEG-1, que todas as plataformas tocam). ENTER salta-o no computador (e também Espaço, ESC e os botões do comando); num ecrã tátil há um botão SKIP (e o botão de voltar do Android). Opções → INTERFACE → "Intro video" desliga-o.
- **Contador de FPS compacto**: sempre no canto superior esquerdo, mais pequeno e com as linhas compridas cortadas.
- **Pausa leve**: o menu de pausa mostra uma imagem parada do jogo em vez de o redesenhar a cada frame (no PC passou de ~18 para ~9 ms por frame; num telemóvel o FPS já não cai no menu de pausa).
- **Recomeçar é quase instantâneo**: as imagens da última música ficam na placa gráfica (até 2 GB, 640 MB no Android), por isso recomeçar (morte, menu de pausa) ou a música seguinte com o mesmo cenário e personagens não as volta a descodificar (Aguacate: 866 ms → 42 ms). Ao voltar aos menus são libertadas.
- **Eventos do Dek Engine**: "Camera rotate on/off" (a câmara balança, valor 2 em graus e valor 1 a velocidade, em tempo real) e "Flash", que o Vs Dek V2 tem dentro do executável. Um script `custom_events` do mod com o mesmo nome tem prioridade.
- **Tweens e timers sem tag como no Psych**: `nil` e `""` também são tags, por isso uma tween nova com a mesma tag para a anterior (o Aguacate cria tweens sem tag a cada frame: já não se acumulam centenas ao mesmo tempo, e o tempo de atualização baixou 6×).

- **Visual novo, mais FNF e retro**: personagens de desenho animado — o jogador **Hype** (gorro lima, casaco azul-céu, auscultadores ao pescoço), **Principal P** (penteado em colmeia violeta, óculos de gatinho e megafone), **DJ Hand** (uma luva de óculos escuros por cima dos pratos) e **D-Mize** (um esqueleto punk de crista vermelha) —, com poses para cada direção e para as falhas e ícones a condizer. Têm um acabamento brilhante **"Frutiger Aero"**: cada forma iluminada de cima, com o reflexo de vidro, contornos azul-escuros, tons aqua, lima e branco, e bolhas de sabão à volta (saem mais do microfone quando cantam). Cenários novos: um telhado de escola ao pôr do sol, uma discoteca (parede de equalizador, bola de espelhos, lasers, público aos saltos), um beco punk debaixo de uma lua vermelha e uma noite synthwave para as músicas dos mods. Menus com estrelas de raios, um sol às riscas, chão em grelha e cubos de vidro a rodar, refletidos no chão; a letra Luckiest Guy nos títulos. As avaliações são **SICK! / GOOD / BAD / WACK**, os rótulos finais são os do Psych (**SFC**, **GFC**, **FC**, **SDCB**, **Clear**, também no `ratingFC` dos scripts) e a contagem é 3, 2, 1, GO!.
- **RENDER MODE e AUTOCHART no menu principal**: o primeiro grava uma música em vídeo; o segundo joga qualquer música com um chart feito a partir do áudio (com as vozes dela, se as tiver).
- **Teclas à tua escolha** (Opções → CONTROLS → "Key bindings (1 to 18 keys)..."): a tecla de cada pista para cada número de teclas, de 1 a 18, mostradas como numa música; ENTER (ou tocar na pista) espera pela tecla nova. Também no Android, para teclados Bluetooth.
- **O melhor do aparelho, e reconhecido como jogo**: nos portáteis com duas placas gráficas o jogo corre na mais rápida (NVIDIA Optimus e AMD no Windows, PRIME/DRI_PRIME no Linux); no Windows a thread do jogo entra na classe "Games" do agendador multimédia e o processo tem prioridade acima do normal; no Linux usa o GameMode, se estiver instalado; no Android declara o Game Mode e manda ao sistema dicas de desempenho (ADPF) com o tempo de cada frame; no macOS a app é da categoria de jogos. O contador de FPS diz o que ficou ativo, e o codificador **Auto** do Render Mode usa o da placa gráfica quando funciona.
- **Até 100 teclas** (também nos charts `.ghc`, versão 2), **pesquisa no Freeplay** (`F`, ou SEARCH no ecrã tátil, como no JS Engine), **definições do Freeplay guardadas** (modificadores, última música e dificuldade) e o **botão CHART** nos ecrãs táteis para abrir o editor de charts a meio de uma música.
- **Quem canta cada nota**: as notas "GF Sing" levam a câmara para a GF (no Aguacate a GF canta do lado do jogador), e os scripts que põem personagens extra a cantar recebem as animações de todas as pistas (o slidenoteification 9).
- **Eventos**: os do V-Slice e os que o P-Slice/H-Slice fazem deles (zoom, alvo e *bops* da câmara, velocidade do scroll), os dos cenários do jogo base (Philly Glow, Kill Henchmen, BG Ghouls, Dadbattle Spotlight, BG Freaks Expression), os do Dek Engine (cores do Flash e velocidade da rotação tiradas do código dele, Invert, Glitch Shader), do Denpa, do Hortas edition e do SCReboot, e scripts próprios para os eventos que as engines antigas tinham por dentro (Blammed Lights, legendas, Cinematics, *fades*, letras...). O script `custom_events` do próprio mod tem sempre prioridade, e o de outro mod com o mesmo nome deixa de ser usado num evento que o jogo já conhece.
- **Scripts e shaders que falhavam**: funções Lua em falta (326 agora), nomes UTF-8 nos scripts, scripts com um `end` a mais ou a menos, shaders com `texture()` ou com o `main` do Shadertoy. `godshand --check-scripts <pasta>` lê os scripts e shaders de uma pasta como uma música e diz os que falham.
- **Interface do Psych sem opção de pasta**: a cópia do Psych/JS Engine é encontrada sozinha (a opção "Psych Engine folder..." saiu).

## English

**Gameplay** – FNF-style call-and-response. Ratings are **SICK! / GOOD / BAD / WACK** (45 / 90 / 135 / 166 ms); clears are named as in Psych Engine: **SFC** (all SICK!), **GFC**, **FC**, **SDCB** (under 10 misses) and **Clear**. The built-in cast are cartoons drawn in code with a glossy "Frutiger Aero" finish: Hype (the player), Principal P, DJ Hand and D-Mize, on a school rooftop at sunset, in a club and in a punk alley.

**Mods**
- Psych Engine mods run in a Flixel-style scene: Sparrow/Packer atlases with trimming, Psych and V-Slice characters, stages (including 0.7.3 stage objects), cameras with zoom/shake/flash/fade, FlxEase tweens, timers, and Lua 5.4 with the Psych API (326 functions, all in the [wiki](docs/wiki/Lua-API.md), and every common callback, persistent save data, custom substates, mod settings, seekable sounds) plus Kade modchart helpers.
- HScript: `runHaxeCode`, `runHaxeFunction`, `createCallback` and `.hx` script files, bridged to `game`, `FlxG`, `FlxSprite`, `FlxText`, `FlxTween`, `FlxTimer`, `FlxColor`, `ShaderFilter`, `FlxRuntimeShader`, `new Character(...)`, `MP4Handler`/`VideoHandler`, `FlxG.cameras`, fully qualified `openfl.*`/`flixel.*`/`lime.*` names and more.
- JS Engine compatibility: its events (Set/Tween Camera Zoom, Camera Bopping, Camera Twist, Change Note Multiplier, Fake Song Length, Change Song Name, Credits Popup, Popup, Rainbow Eyesore, Bot Energy...), its screen effects (`addChromaticAbberationEffect`, `addVCREffect`, `addWiggleEffect`, `addBloomEffect`, `add3DEffect`... with JS Engine's own GLSL) and functions such as `require`, `saveFile`, `loopTheSong`, `playsAsBF`. The camera follows Psych (`camFollowPos` is the real position, per-section focus with `gfSection`, `isCameraOnForcedPos`); scripts that change `FlxG.width` (e.g. *Window Changer*) narrow the picture to 4:3. Of 1048 Lua scripts from JS Engine mods, 984 run without an error in the headless corpus check.

Long tracks keep only the minutes around the play position in memory; Freeplay previews start at once too.

The FPS counter says what was set up, and Render Mode's **Auto** encoder uses the graphics card's when it works.

**Android** – `GodsHand-android.apk` (Android 7+, arm64/armv7/x86_64). On-screen arrows, OK and BACK in the menus; during a song the whole screen is split into the lanes, with a PAUSE button (the system back button pauses too). Shaders run as GLSL ES 1.0; `.mp4`/`.webm` videos need ffmpeg, which Android does not have (`.mpg` plays). Built with `android/build_apk.sh` (NDK + CMake, a small Java activity for fullscreen and the file picker); signed with `android/godshand.keystore` (password `godshand`) so every build installs over the previous one, or with your own key through the `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASS` repository secrets.

**Offline source package** – `tools/make_source_package.sh` packs the game with the exact sources of raylib, Lua, miniz and pl_mpeg in `third_party/` (used automatically by CMake), so it builds without internet. Since 1.6.3 it is no longer published with the releases.

**Engine** – the song position comes from the audio mixer's frame counter; input is polled at ~1 kHz with timestamps; song audio (Ogg Vorbis, MP3, WAV) is decoded in the background in blocks with raylib's own decoders (`audio_decode`). Pure-logic core (`json`, `chart`, `chart_stream`, `song_scan`, `flp_import`, `session`, `synth`, `composer`, `psych`, `scene`, `lua_host`, `hscript`, `shader_glsl`, `basegame`, `autochart`, `replay`, `mod_install`) with a headless test suite:
```sh
build/gh_tests                          # all tests (add --audio to render the songs too)
build/gh_tests --chart a.json b.json    # parse/benchmark charts of any size
build/gh_tests --psych-corpus mods/     # load every atlas, character, stage and Lua script in a mod folder
build/gh_tests --flp song.flp           # what an FL Studio project holds, as SNIFF reads it
build/godshand --list-songs --base dir/ # what the song library finds in dir/songs and dir/mods
build/godshand --list-songs --check-charts --base dir/  # ...and load every chart (keys, notes or the error)
```

**Layout**
```
src/        engine + game (C++20, raylib for window/audio/drawing, Lua 5.4, miniz, pl_mpeg)
src/asm/    the note renderer's assembly: x86-64 (GAS for GCC/Clang, MASM for MSVC) and ARM64 (NEON)
android/    APK build: manifest, icons, Java activity, build and emulator test scripts
tools/      complete source package
tests/      headless tests, chart benchmark and mod corpus checker
assets/     fonts (SIL OFL)
songs/      your own songs (charts, or just audio for AutoChart)
modpacks/   the list of mod packs and the script that publishes them
licenses/   third-party license texts (Apache 2.0)
mods/       Psych Engine / FNF mods, folders or .zip (created next to the executable)
replays/    recorded runs     saves/  script save data     cache/  converted videos     renders/  recorded videos
```
