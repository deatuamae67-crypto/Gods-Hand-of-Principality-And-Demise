# God's Hand of Principality and Demise

A rhythm duel in the style of Friday Night Funkin', written from scratch in **C++20** with its own cast drawn in Friday Night Funkin's style, merged with the best of **PulseForge**:
it plays Psych Engine mods (Lua and HScript, characters, stages, events, shaders, videos), full Kade/base-game builds and
spam charts of any size, has chart, character, stage, event and script editors, charts any song by itself, records replays and videos,
and installs mods from `.zip`. A project by **deatuamae67-crypto**.

**Downloads:** [Releases](https://github.com/deatuamae67-crypto/Gods-Hand-of-Principality-And-Demise/releases)
- Windows / Linux / macOS: extract the zip and run `godshand` (`godshand.exe` on Windows).
- Windows Vista, 7 and 8, 32-bit Windows, and older graphics cards (OpenGL 2.1): `GodsHand-windows-vista-7-x86.zip`.
- Android 7+: install `GodsHand-android.apk` (allow installing from that source when asked).
- Only the newest version is published (plus the mod packs). The game updates itself from here (Options → INTERFACE → Auto-update): a newer version is downloaded, checked and installed the next time it starts.

**Mod packs:** release [`mods`](https://github.com/deatuamae67-crypto/Gods-Hand-of-Principality-And-Demise/releases/tag/mods), or MOD PACKS (`M`) in Freeplay. Not all of the mods are by deatuamae67-crypto: some are, and the others belong to their original creators.

## The game

- **An FNF-style rhythm duel**: the opponent sings, you answer. Arrows going up (or down), holds, a health bar, combo, score, accuracy and ranks. Ratings are **SICK! / GOOD / BAD / WACK** (45 / 90 / 135 / 166 ms); clears are named as in Psych Engine: **SFC** (all SICK!), **GFC**, **FC**, **SDCB** (under 10 misses) and **Clear**.
- **4 original songs** synthesized in C++ when the game starts (drums, bass, pads, bells and "sung" voices), with charts made from their own melodies. The built-in cast is drawn in code in Friday Night Funkin's style — Hype (the player), Principal P, DJ Hand and D-Mize — on a school rooftop at sunset, in a club and in a punk alley.
- **Fast and exact**: the song's clock comes from the audio mixer, the keys are read about 1000 times a second with timestamps, and judging does not depend on the frame rate.

## Mods

- Psych Engine mods run in a Flixel-style scene: Sparrow/Packer atlases with trimming, Psych and V-Slice characters (`characters/*.json`) with their icons and health bar colours, stages (`stages/*.json`, including 0.7.3 stage objects), events, note types, cameras with zoom/shake/flash/fade, FlxEase tweens, timers, and Lua 5.4 with the Psych API (326 functions, all in the [wiki](docs/wiki/Lua-API.md), and every common callback, persistent save data, custom substates, mod settings, seekable sounds) plus Kade modchart helpers.
- HScript: `runHaxeCode`, `runHaxeFunction`, `createCallback` and `.hx` script files (in `scripts/`, `stages/`, `data/<song>/`...), bridged to `game`, `FlxG`, `FlxSprite`, `FlxText`, `FlxTween`, `FlxTimer`, `FlxColor`, `ShaderFilter`, `FlxRuntimeShader`, `new Character(...)` (extra characters), `MP4Handler`/`VideoHandler`, `FlxG.cameras`, fully qualified `openfl.*`/`flixel.*`/`lime.*` names and more.
- JS Engine compatibility: its events (Set/Tween Camera Zoom, Camera Bopping, Camera Twist, Change Note Multiplier, Fake Song Length, Change Song Name, Credits Popup, Popup, Rainbow Eyesore, Bot Energy...), its screen effects (`addChromaticAbberationEffect`, `addVCREffect`, `addWiggleEffect`, `addBloomEffect`, `add3DEffect`... with JS Engine's own GLSL) and functions such as `require`, `saveFile`, `loopTheSong`, `playsAsBF`. The camera follows Psych (`camFollowPos` is the real position, per-section focus with `gfSection`, `isCameraOnForcedPos`); scripts that change `FlxG.width` (e.g. *Window Changer*) narrow the picture to 4:3. Of 1048 Lua scripts from JS Engine mods, 984 run without an error in the headless corpus check.
- Shaders: Psych/Flixel `.frag` shaders (`#pragma header`, `flixel_texture2D`) are translated to GLSL 330 and run on sprites (`setSpriteShader`) and whole cameras (`setFilters` in HScript). On a `makeGraphic` sprite a shader sees the whole picture (coordinates 0 to 1), and `os.clock()` counts real time on every system, as on Windows: shaders animated with `iTime` change smoothly.
- Videos: `startVideo` cutscenes (ENTER skips them) and `makeVideoSprite` with pl_mpeg. `.mpg` files play directly; `.mp4`/`.webm` are converted once with **ffmpeg** (installed or next to the game) into `cache/videos/`.
- Full Kade/base-game builds: the week 1–6 characters, stages and stage behaviour are rebuilt from the mod's own images.
- Any folder layout: nested mod folders, loose charts grouped by song with audio found across mods, V-Slice, full builds with charts in `assets/preload/data/` or `assets/shared/data/` and audio in `assets/songs/` (Psych 0.4–0.7, H-Slice, Psych EK), a build's `mods/` folder with mods inside, `data/charts/<song>/`, charts loose in `data/`, a compiled build inside a source tree (`export/release/.../bin/`: identical copies of a chart are offered once; different versions both appear, labelled with their folder), **PulseForge charts** (exported `chart.json`, editor `.pfchart.json` projects and autosaves, streamed when huge) and **audio-only folders** (every track of 30 s or more gets AutoChart; short sound effects are left out). 1–1024 keys (`keyCount` up to 1024, or `mania` from Dave & Bambi / Kade / Andromeda, Psych Extra Keys up to 18 keys (`mania` 17), Denpa (`options.mania`) and Shaggy: the notes decide which numbering a chart uses, and a `mania` the notes do not use — like the `options.mania` of JS Engine spam charts — gives 4 keys; without either a chart has 4 keys, as in Psych). Leather Engine charts with a different key count for each side (`keyCount` and `playerKeyCount`) play that way, and scripts that fake extra keys in a 4-key engine (the *Extra Keys Script* of JS Engine mods) do not run, since the game plays the keys itself. Options → "Extra keys" OFF plays everything with 4 keys. From 19 to 1024 keys the lanes narrow to fit and take the keyboard's keys row by row (43 keys); the bot plays the lanes past them.
- Huge spam charts are streamed: 1.5 GB / 25 million notes load in about 5 s with bounded memory. Notes stacked in one millisecond stay merged in memory but every one of them counts (hits, combo, score, totals), notes are drawn down to one pixel apart (with Options → "Note detail: Adaptive", while the frame rate stays under 60 with hundreds of notes on screen, notes stacked closer than 2–32 px are drawn once; every note is still played and counted), and charts without a key count are 4-key charts, as in Psych and JS Engine.
- Songs start at once: song audio is decoded while it plays (the S2X engine's idea of reading the chart while the song runs, applied to audio). A 3-minute song is ready in ~2 ms instead of 0.75 s, a 1-hour one in 2.5 ms instead of 6 s (21 MB instead of 1.2 GB), and LONGSONG's 8-hour Desert Bus no longer crashes the game. Long tracks keep only the minutes around the play position in memory; Freeplay previews start at once too.
- Assets are shared between mods: a character, stage, image, sound, video, shader or font a mod uses but does not have is looked up in the rest of its own pack first, then in every other installed mod (asset-only packs such as `lmac-orien-sprites` and `lmac-denpaex-reconstructed` exist for this). A borrowed stage, character, note type or event brings its own script; the other mod's global scripts (`scripts/`) do not run. For example the "18th-Victim" autosave in `pulseforge-created` plays with the stage, characters, icons and audio of the vs dinnerbambi pack.
- Windows builds use UTF-8 as their code page (Windows 10 1903+), so folders and files named in any alphabet (Chinese, Japanese, Cyrillic...) open.
- Scripts are sandboxed (no `io` or `os`; `require` reads only the mod's own modules and `saveFile` writes only inside `mods/`) and stopped if they loop forever.

## Features

- **Chart editor** (Freeplay `7`, or `7` during a song, on that song and difficulty), as Psych's and JS Engine's: **Song** (name, characters, stage, BPM, speed, keys), **Section** (camera side, GF section, alt animation, length in beats, BPM; copy, paste, clear, swap sides, mirror, copy from an earlier section), **Note** (type, time, hold, stacked notes; spam tools: stack, fill the section as stairs, random, zigzag...), **Events** (the events lane on the left, several events at the same time, a list with Psych's, JS Engine's and the mod's `custom_events` explaining their values), **Charting** (playback rate, volumes, hitsounds, metronome) and **EZ Spam** (spam over the section, to the end, the whole song or a range of sections, with notes per beat, pattern (single lane, stairs, random, zigzag, chords, jacks), side, holds and stacks; also clear and thin out) tabs; box selection (SHIFT+drag), undo/redo, and `ENTER` saves and plays; JS Engine's Note Spamming tab (spam, stretch, shift, duplicate), odd time signatures (7/16, 5/4...), copying and cutting whole sections, `SHIFT+A`/`SHIFT+D` to jump 4 sections, the opponent's hitsound equal to the player's; saves Psych JSON (the original is kept as `.bak`). **FL Studio charts the SNIFF way**: drop a `.flp`/`.fsc` on the editor and the pattern's notes (C3–D#3 the player, C4–D#4 the opponent, F3/F#3 the camera, A3/A#3 alt animation) go into the chart; FL Studio chart projects in mods are listed as songs, one difficulty per pattern.
- **Editors** (main menu `7`), as Psych's Master Editor Menu: pick the mod they save into (LEFT/RIGHT), then the chart editor, the **character editor** (the character drawn as in a song; animations with the image's own names to pick the prefix from, offsets with the arrows (SHIFT ×10) over a ghost of the first animation, image, scale, flip, antialiasing, health icon and bar colour, position, camera point, sing duration; `CTRL+S` saves `characters/<name>.json`), the **stage editor** (objects, the stage script's sprites and three characters dragged into place with the mouse, zoom, camera speed, pixel stages, hiding GF, camera offsets and what the camera shows of each character; saves `stages/<name>.json`) or the **event editor** (custom events for charts, `custom_events/<name>.txt` and `.lua`, from templates: flash, HUD fade, shake, zoom, sound, scroll speed; the script opens in the system's text editor). Saved files keep the fields the editors do not know.
- **AutoChart** for songs without charts, deterministic **replays** (`R` on the results), `.zip` mod installs, the in-game **mod pack downloader** (Freeplay `M`) and, on Android, **touch controls**. With Options → INTERFACE → "AutoChart", **AUTOCHART** on the main menu opens a screen laid out as FL Studio (a channel rack with each sound's role, lanes and amount; a playlist with the waveforms and an `.flp` project's notes; a tempo lane) and a model that learns from your mods' charts. AutoChart's charts are saved only as `.ghac`, which no other engine reads, and show "AUTOCHARTED" for the whole song.
- **JSON merging** (Options → INTERFACE → "JSON merging"): a chart split into parts (as players do to get past JS Engine's 16-million-note limit) becomes one again, with no note limit — the parts picked in the system's file manager, laid over each other or one after another; `godshand --merge` too.
- **Auto-update** (Options → INTERFACE → "Auto-update"): at start, the game looks for a newer version on GitHub, downloads it, checks it (SHA-256) and installs it the next time it starts (UPDATE on the main menu restarts now; on Android, UPDATE opens the new version's download in the browser, to install from there: the game itself never installs apps, so app scanners such as Google Play Protect have nothing to flag). It also finds changes in the mod packs you installed: MOD PACKS shows them, to install or remove. Settings, scores and mods stay.
- **Psych Engine interface** (Options → INTERFACE): the Psych look and sounds, read from a Psych Engine / JS Engine copy the player already has (found by itself among engine builds installed as mod packs, such as JS Engine, H-Slice and EZ edition, or an engine such as S2X in or next to the game's folder). None of those files ship with the game. It is laid out as Psych 0.7.3's PlayState: health bar, icons, score, time bar and text, BOTPLAY, rating popups and combo digits at Psych's places, sizes and motions, `vcr.ttf` at its real size, and Psych's pause menu (Alphabet letters, `breakfast` or `tea time`, "Blueballed"). A song's own mod comes first for fonts, health bar, notes, ratings and sounds.
- **Psych's options**: Hide HUD, Score text zoom on hit, Botplay text, Combo stacking, Pause screen song, Opponent notes, hit popups, time bar (time left / elapsed / song name / off), health bar opacity, Rating offset, Sick!/Good/Bad hit windows and Safe frames (they change how notes are judged; replays keep them), Auto pause, Disable reset button, Anti-aliasing, note splash opacity, Note skin... (a screen of its own: the skins of your Psych copy and of every installed mod, with the chosen one's notes going by beside them, as in a song), Note colors (hue, saturation and brightness per arrow) and the rating and combo positions. Scripts asking for them (`ClientPrefs`, `getPropertyFromClass`) get the chosen values.
- **Scripts and the HUD**: fades (`doTweenAlpha` on `scoreTxt`, `timeTxt`, `timeBar`, `healthBarBG`...) fade it, and `setProperty` moves, rotates and scales the health bar, icons, score, time bar and text and BOTPLAY as in Psych. They start at Psych 0.7.3's positions (`getProperty('healthBar.y')` is 640.8), and the score shows what scripts change at once (`addScore`, `setScore`, `setRatingName`...).
- **Camera and zoom as in Psych / JS Engine**: "Add Camera Zoom" adds up and stays until the first note is hit; "Camera zoom on beat" only turns off the beat bops (Eons pulls the camera back at the start and closer on each bar of its intro). VSync applies at once (Android too); a Shaders switch helps weak devices; shaders on `makeGraphic` sprites see the whole sprite and `os.clock()` counts real time on every system.
- **Volume anywhere**: `-` / `=` (or the keypad's `+`) change it and `0` mutes it, as in Flixel and Psych; the volume shows at the top of the screen, and a screen that uses those keys (a lane, typing in an editor) keeps them. The pause menu has Options (leaving them restarts the song, as in Psych).
- **Options → DEBUG**: Lua errors and warnings always, only for scripts with `luaDebugMode` (as in Psych), or never (scripts' `debugPrint` always shows); "Lua note callbacks" OFF skips `goodNoteHit`, `opponentNoteHit`, `noteMiss` and `noteMissPress` on every note (faster spam charts, as S2X's option; mods that count notes or drain health through them stop doing so).
- **Render Mode** (main menu → RENDER MODE, desktop and Android; the video settings are in Options → RENDER MODE VIDEOS), as in JS Engine and H-Slice: songs play by themselves and are recorded to a video in `renders/`, frame by frame. Game time moves exactly 1/fps per frame, so the video is smooth even when the computer cannot draw in real time; the window shows what is being recorded and how much is left. Size 1280x720 to 3840x2160, 30 to 240 fps, Auto (the graphics card's encoder when it works on this computer), x264, x265, VP9/WebM or the NVIDIA, AMD and Intel hardware encoders, bitrate, and the song's audio. On a computer it needs **ffmpeg** next to the game or installed; frames leave the graphics card without making it wait (read two frames later) and are encoded on a thread of their own while the game draws the next ones. On **Android** it uses the phone's own encoders (H.264 and AAC, no ffmpeg) and the video goes to **Movies/GodsHand** (Android 10 or later), where the gallery shows it. `ESC` (or STOP on touchscreens) stops and keeps what was recorded; `godshand --autoplay <song> --render` records from the command line.
- **Debug overlay** (`F3` during a song, as S2X's debug menu): the chart, the clock (time, beat, step, section), audio (decoded blocks and MB in memory), notes drawn, frames per second, update and draw times, scripts; `godshand --perf` prints frame times every second.
- **Detailed FPS counter** (Options → GRAPHICS): the game's memory and its peak, frame times with a graph, processor, graphics card (how busy it is and its video memory, on Windows, Linux with AMD or NVIDIA, macOS and Adreno/Mali phones that allow it) and system memory use, and the processor, graphics card, OpenGL version and system; red at half the frame limit, as Psych's.
- **Note renderer** (Options → GRAPHICS): notes drawn by the graphics card (**GPU**) or by the processor, with an **assembly** routine — **CPU (x86 ASM)** with SSE2 on x86-64 computers, **CPU (ARM64 ASM)** with NEON on Android phones and Apple Silicon Macs — or in **C++** — **CPU (C++)**. On the processor every note is a picture made once (skin, colours, size) and blended into a picture of the screen, row by row and only over the columns the arrow covers, which reaches the graphics card in one piece. **Auto** (the default) uses the graphics card, or the assembly when OpenGL itself runs on the processor (llvmpipe, SwiftShader...), where it is faster. Turned notes and mines stay on the GPU. The assembly gives exactly the C++ version's pixels (the tests compare them, on Windows and on an ARM Mac too) and is about 3× faster. `F3` and `godshand --perf` show the time it takes.
- **Lowest latency**: with V-sync, **Low latency** (Options → GRAPHICS, on by default) keeps no frames waiting in the driver and starts each frame as late as it can before the screen shows it, reading the keys every millisecond meanwhile (on a simulated 60 Hz screen: ~5 ms from a key to the screen instead of 16.7). **Audio latency** (Options → GAMEPLAY) picks the sound card's buffer: 6, 15 (the default, was 30), 30 or 60 ms. Without V-sync the game already reads the keys ~1000 times a second.
- **Fast loading**: character and stage pictures are decoded on every processor core at once (12 pictures of 2048x2048: 0.65 s instead of 2.6 s). Charts from 8 MB on are streamed by a thread of their own ahead of the parser, their sections shared out to every core and JSON's structural characters found 64 bytes at a time with SIMD instructions (SSE2 on x86-64, NEON on ARM64): a 20 MB chart loads in ~40 ms (was 134 ms), a 200 MB one in ~0.3 s (was ~0.6 s) and 3 GB of the 1.4-billion-note chart in 3.2 s instead of 7.7 s (the whole chart, 33 GB, takes only ~300 MB of memory). JSON numbers of up to 18 digits (as Haxe writes them) no longer go through `strtod`. Big charts are kept in a cache (`cache/charts/` in the user's folder, up to 4 GB): the second time, a 200 MB one loads in 0.2 s. The result is always exactly what one core gives (the tests compare them). `godshand --perf` shows where the loading time goes.
- **Note counter** under the score: your side, or both sides as H-Slice shows them (`opponent + yours = both`), with each side's NPS. Score, combo, misses and every count are exact 256-bit numbers, and long numbers shrink to fit.
- **Settings in the user's folder** (`%APPDATA%\GodsHand`, `~/Library/Application Support/GodsHand`, `~/.local/share/GodsHand`, the app's folder on Android), so updates keep them (the old ones are copied once; `portable.txt` next to the game keeps everything there). Freeplay modifiers (`Tab`) set the scroll speed: the chart's, multiplied, or constant.
- **JS Engine's effects as the originals**: `addBlockedGlitchEffect`, `addVCREffect`, `addGrainEffect` and the others use the GLSL of JS Engine's `Shaders.hx` (they were imitations before).
- **Shader layers**: several shaders on one sprite, each working on what the one before it drew, with `addSpriteShader`, `removeSpriteShader`, `getSpriteShaders`, `moveSpriteShader` and `setSpriteShaderOrder`; `setShaderFloat` and the others take the layer (its position or shader name). See the [wiki](docs/wiki/Shaders.md).
- **More faithful HScript**: comprehensions (`[for (i in 0...4) i * i]`), functions returning without braces, groups (`FlxTypedGroup`, `FlxSpriteGroup`), `game.members`, `Date`, `Type`, `Sys`, `FlxEase` called as a function, `velocity` and `acceleration` as in Flixel; Psych 0.7.3's `createInstance`/`addInstance`. Scripts with several characters (such as Expunged's *old.lua*) work.
- **Tweens on HUD objects**: `doTweenY`, `doTweenAlpha`... reach `iconP1`, `healthBar`, `scoreTxt` and the rest, and `setObjectOrder` works as in Psych (sprites not added yet too).
- **Awkward atlases**: frames that reach past the image are clipped as in Flixel, and frames sharing a name keep the first, as in Flixel (scrodo-v2's right pose).
- **A chart editor for charts of millions of notes**: it draws only what is on screen, one note per pixel row, texture by texture, and undo keeps only what changed (3.42 million notes, software OpenGL: 45 ms a frame instead of 110, 20 ms in a small window). Also **Reload audio** and **Reload chart**, numbers typed into every field (click the number), each side's hitsound volume, an uncapped "Sections back", copying a range of sections (as in JS Engine), **Exact placement** (a note at a section's start right after one at the end of the section before) and a small chart preview window.
- **Granular hitsounds**: each note plays on its own sample of the song and the notes do not pile up: a fast spam becomes a tone at the rate of its notes (16 notes a step at 520 BPM sound at 555 Hz) instead of a loud, crackling noise.
- **Binary `.ghc` charts**: the chart with its notes in packed columns, read on every core: a chart of 3.42 million notes goes from 201 MB to 2.4 MB (84.6× smaller) and loads in 150 ms instead of 240. Made in the **Chart Converter** (editors menu) or in the chart editor, which saves as Psych JSON, `.ghc` or both; the `.ghc` is written straight from the notes, so a chart too big for JSON can be kept as `.ghc` alone.
- **Script editor** (editors menu): the mod's Lua and HScript scripts and shaders, edited in the game. **Stage editor objects**: pick, drag, properties, layers, add, copy and delete the JSON's objects, saved as Psych 0.7.3 objects; the stage runs in the editor with its scripts and shaders.
- **Wiki** in [`docs/wiki`](docs/wiki/Home.md): the 326 Lua functions, the callbacks, HScript, shaders, chart formats, editors, mods and every option.
- **Audio visualizer** (Options → INTERFACE → "Audio visualizer"): rounded, glossy bars on a pane of glass in the top-right corner of songs that move with the sound (an FFT of what is heard, 40 Hz to 16 kHz; each bar jumps up and falls slowly). A line of light runs over their tips, the peaks hang a moment as dots, tall bars glow, a reflection sits under a floor of light, and the pane's rim lights up with the bass. Its colour follows the chart: the colour of whoever's section it is, warmer the thicker the notes, a running rainbow in spam, a flash in the rating's colour on each of your hits, red and shaking when you miss, and throbbing on the beat when your health is low. It only shows in songs.
- **Watermark**: "God's Hand Engine v.2.3.0 Windows Edition" (the version and the system) in the bottom-left corner of songs, as JS Engine shows its own (Options → INTERFACE → "Watermark").
- **A compact FPS counter**: always in the top-left corner, smaller, long lines cut short.
- **A light pause menu**: it shows a still picture of the game instead of drawing it again every frame (on a PC from ~18 to ~9 ms a frame; a phone keeps its frame rate in the pause menu).
- **Restarting is nearly instant**: the last song's pictures stay on the graphics card (up to 2 GB, 640 MB on Android), so a restart (after dying, from the pause menu) or the next song with the same stage and characters does not decode them again (Aguacate: 866 ms → 42 ms). Going back to the menus frees them.
- **Dek Engine events**: "Camera rotate on/off" (the camera sways, value 2 in degrees and value 1 its speed, in real time) and "Flash", which Vs Dek V2 has built into its executable. A mod's own `custom_events` script of the same name wins.
- **Untagged tweens and timers as in Psych**: `nil` and `""` are tags too, so a new tween under the same tag stops the last (Aguacate starts untagged tweens every frame: hundreds no longer pile up, and its update time fell 6×).

- **A new look, more FNF and retro**: cartoon characters — the player **Hype** (lime beanie, sky-blue hoodie, headphones round the neck), **Principal P** (violet beehive, cat-eye glasses, a megaphone), **DJ Hand** (a glove in shades over the decks) and **D-Mize** (a punk skeleton with a red mohawk) — with poses for every direction and for misses, and matching icons. They are drawn as **Friday Night Funkin'** draws its cast (since 2.1.0): thick dark outlines, flat colours with a coloured shade on every shape, strong poses, as large on stage as FNF's characters. New stages: a school rooftop at sunset, a club (equalizer wall, mirror ball, lasers, a crowd jumping on the beat), a punk alley under a red moon, and a synthwave night for mod songs. Menus with rayed stars, a striped sun, a grid floor and glassy cubes turning in the air, mirrored in the floor; the Luckiest Guy font for titles. Ratings are **SICK! / GOOD / BAD / WACK**, clears use Psych's names (**SFC**, **GFC**, **FC**, **SDCB**, **Clear**, `ratingFC` for scripts too), and the countdown is 3, 2, 1, GO!.
- **RENDER MODE and AUTOCHART on the main menu**: one records a song to a video; the other plays any song with a chart made from its audio (its own voices along, when it has them).
- **Your own keys** (Options → CONTROLS → "Key bindings (1 to 18 keys)..."): the key of every lane for each key count from 1 to 18, shown as in a song; ENTER (or a tap on the lane) waits for the new key. On Android too, for Bluetooth keyboards.
- **The device's best parts, and known as a game**: on laptops with two graphics cards the game runs on the fast one (NVIDIA Optimus and AMD on Windows, PRIME/DRI_PRIME on Linux); on Windows the game thread joins the multimedia scheduler's "Games" class and the process runs above normal priority; on Linux it uses GameMode when installed; on Android it declares Game Mode and sends the system performance hints (ADPF) with each frame's work; on macOS the app is in the games category. The FPS counter says what was set up, and Render Mode's **Auto** encoder uses the graphics card's when it works.
- **Up to 100 keys** (in `.ghc` charts too, version 2), **Freeplay search** (`F`, or SEARCH on touchscreens, as in JS Engine), **Freeplay settings saved** (modifiers, last song and difficulty), and a **CHART button** on touchscreens to open the chart editor mid-song.
- **Who sings each note**: "GF Sing" notes take the camera to GF (in Aguacate GF sings on the player's side), and scripts that make extra characters sing get the sing animations of every lane (slidenoteification 9).
- **Events**: V-Slice's and the ones P-Slice/H-Slice make of them (camera zoom, target and bops, scroll speed), the base game's stage events (Philly Glow, Kill Henchmen, BG Ghouls, Dadbattle Spotlight, BG Freaks Expression), Dek Engine's (Flash colours and rotation speed from its source, Invert, Glitch Shader), Denpa's, Hortas edition's and SCReboot's, and scripts for the events older engines had built in (Blammed Lights, subtitles, Cinematics, fades, lyrics...). The song's own mod's `custom_events` script always wins, and another mod's script of the same name is no longer borrowed for an event the game knows.
- **Scripts and shaders that failed**: missing Lua functions (326 now), UTF-8 names in scripts, scripts with an `end` too many or too few, shaders with `texture()` or a Shadertoy `main`. `godshand --check-scripts <folder>` reads a folder's scripts and shaders as a song would and lists those that fail.
- **Psych interface without a folder option**: the Psych/JS Engine copy is found by itself (the "Psych Engine folder..." option is gone).
- **Charts in every size**: the game reads and writes God's Hand's binary `.ghc`, its count charts `.ghn`, the bigit `.ghb` (the whole chart as one arithmetic-coded number, the smallest of all) — all three with counts of any size —, the iutk engine's FNC1 `.bin`, R-Slice's `.raid` and the threadripper engine's `.thr`; `godshand --convert <chart> <out>` turns any of them into any other (see the [wiki](docs/wiki/Charts.md)).
- **A whole FL Studio project as one chart**, as SNIFF reads a pattern but over the song's playlist (SNIFF's own to-do): `song.flp#playlist` has every note of every channel through every clip, counted, from FL Studio 20 to 26; a 4 GB project of 3.56 trillion notes reads in about 6 s. `godshand --max-notes` makes charts of 2^256 − 1 notes, the most the game counts.
- **Motion blur** (Options → GRAPHICS: Off, Light, Medium, Strong): in songs each frame keeps a little of the ones before, the same at any frame rate; in Rendering mode each video frame is the average of 2, 4 or 8 drawn between it and the next.
- **Credits with pictures**: the owners and contributors with their own profile pictures, as Psych lays its credits out.
- **A title screen with a background** in the Psych look: menuDesat in a deep violet bumping on the beat, with Principal P dancing where Psych's GF stands when the Psych copy has no GF.

## Android

`GodsHand-android.apk` (Android 7+, arm64/armv7/x86_64). On-screen arrows, OK and BACK in the menus; during a song the whole screen is split into the lanes (touch anywhere in a column), with a PAUSE button (the system back button pauses too). Freeplay has MOD PACKS (download) and IMPORT ZIP (system file picker). Game files live in `Android/data/com.godshand.game/files/` (`mods/`, `songs/`, `replays/`...). The app pauses and goes silent in the background. Shaders and Lua/HScript work as on a computer (shaders as GLSL ES 1.0); `.mp4`/`.webm` videos need ffmpeg, which Android does not have (`.mpg` plays). Built with `android/build_apk.sh` (NDK + CMake, a small Java activity for fullscreen and the file picker); signed with `android/godshand.keystore` (password `godshand`) so every build installs over the previous one, or with your own key through the `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASS` repository secrets.

## Building

CMake 3.20 or later and a C++20 compiler. raylib 5.5, Lua 5.4.7, miniz, pl_mpeg and zstd 1.5.6 are downloaded by themselves.
```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/godshand          # Windows: build\Release\godshand.exe (MSVC) or build\godshand.exe
```
Linux needs `libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libgl1-mesa-dev libasound2-dev`.
A Windows `.exe` from Linux: `-DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-x86_64.cmake`.
Android: with the Android SDK (`platforms;android-34`, `build-tools;34.0.0`, `ndk;27.2.12479018`), a JDK, Ninja and zip,
`ANDROID_SDK=/path/to/android-sdk android/build_apk.sh` makes `build/GodsHand-android.apk`.
The icon: `godshand --make-icon <folder>` draws it, and `python3 tools/make_icons.py <folder>` makes `src/windows/godshand.ico` and the Android icons.

**Offline source package**: `tools/make_source_package.sh` packs the game with the exact sources of raylib, Lua, miniz, pl_mpeg and zstd in `third_party/` (used by CMake by itself), so it builds without internet. Since 1.6.3 it is not published with the releases (it is on the Google Drive).

## Engine

the song position comes from the audio mixer's frame counter; input is polled at ~1 kHz with timestamps; song audio (Ogg Vorbis, MP3, WAV) is decoded in the background in blocks with raylib's own decoders (`audio_decode`). Pure-logic core (`json`, `chart`, `chart_stream`, `song_scan`, `flp_import`, `session`, `synth`, `composer`, `psych`, `scene`, `lua_host`, `hscript`, `shader_glsl`, `basegame`, `autochart`, `replay`, `mod_install`) with a headless test suite:
```sh
build/gh_tests                          # all tests (add --audio to render the songs too)
build/gh_tests --chart a.json b.json    # parse/benchmark charts of any size
build/gh_tests --psych-corpus mods/     # load every atlas, character, stage and Lua script in a mod folder
build/gh_tests --flp song.flp           # what an FL Studio project holds, as SNIFF reads it
build/godshand --list-songs --base dir/ # what the song library finds in dir/songs and dir/mods
build/godshand --list-songs --check-charts --base dir/  # ...and load every chart (keys, notes or the error)
build/godshand --convert "song.flp#playlist" song.ghn  # a whole FL Studio project, every note, as one chart
build/godshand --max-notes out.ghb 36000 125000 120 "Title"  # 2^256 - 1 notes, the player's, 36 s to 125 s
```

## Why it is built this way

PulseForge grew too big to keep up (the Discord SDK, streaming billions of notes, content in LFS in its own repository). Here God's Hand's small, tested core is the base and the best of PulseForge was written again on top of it, with tests. The mods' content lives outside the code: packs on the `mods` release, made once from PulseForge's LFS by the *Mod packs* workflow, or copied from zips made with `modpacks/build_packs.py --local` and shared on Google Drive (the `drive` lines of `modpacks/packs.txt`), or packed from this repository's own `modpacks/<folder>/` (the `local` lines: the charts made with the game).

## Layout

```
src/        engine + game (C++20, raylib for window/audio/drawing, Lua 5.4, miniz, pl_mpeg, zstd)
src/asm/    the note renderer's assembly: x86-64 (GAS for GCC/Clang, MASM for MSVC) and ARM64 (NEON)
android/    APK build: manifest, icons, Java activity, build and emulator test scripts
tools/      complete source package
tests/      headless tests, chart benchmark and mod corpus checker
assets/     fonts (SIL OFL)
songs/      your own songs (charts, or just audio for AutoChart)
modpacks/   the list of mod packs and the script that publishes them
licenses/   third-party license texts (Apache 2.0)
mods/       Psych Engine / FNF mods, folders or .zip (created next to the executable)
replays/    recorded runs     saves/  script save data     cache/  converted videos     renders/  recorded videos
```
